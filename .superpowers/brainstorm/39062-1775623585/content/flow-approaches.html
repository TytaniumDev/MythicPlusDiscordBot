Auto-Advance Spin Flow

How the spin sequence progresses from start to finish

Proposed Timeline (per group)

🎡 Wheels Spin
~4s (grid) / ~12s (carousel)
→
⭐ Group Card Spotlight
3 seconds
→
✨ Fade
~0.5s
↻ Repeats for each group, then auto-transitions to Results View

Two Approaches

How to orchestrate the server-driven auto-advance

A

Server Reveals All at Once — Client Staggers

When user clicks "Spin", the bot writes all groups to Firestore at once (revealedGroups = total). Each client independently animates through them with built-in delays (spin + 3s spotlight + fade), auto-advancing locally.

Pros

  • Single Firestore write — simple
  • No server-side timer needed
  • Works even if bot goes offline mid-sequence

Cons

  • Clients may drift slightly out of sync
  • Late-joining clients need catch-up logic

⭐ Recommended — Simpler, more robust. Slight client drift is imperceptible in practice since users are on their own screens.

B

Server Reveals One-by-One on Timer

Bot increments revealedGroups in Firestore on a timer (every ~7.5s for grid, ~16s for carousel). Each client animates in response to the Firestore update.

Pros

  • All clients perfectly in sync
  • Server controls pacing

Cons

  • Requires bot-side timer coordination
  • Server must know client animation durations
  • If bot disconnects mid-sequence, spin stalls
  • Layout mode affects timing — server needs to pick one
